# News event candidates (V4.05)

Experimental offline API. `cluster_news_events(observations, as_of=..., hints=(), previous=())` groups bounded, immutable headline observations into candidate events, not verified occurrences. No new dependency, network, database or MCP registry change.

- Automatic baseline: exact normalized sufficiently long headlines, a single recognized action, compatible reported publication or provider-seen timestamps (maximum 24h apart), no conflicting factual markers, explicit dates or language labels. Unknown report time abstains unless a shared explicit calendar-day literal is available. Questions and assertions do not collapse.
- Optional EventHint annotations: exact nonoverlapping source spans, entity and location labels literally anchored in the span. Supports multiple mentions of one headline. Annotations are not inferred identities or verified labels. For different headlines, matching literal entity and location sets, explicit ISO event day and recognized action are required; same-language cases additionally need token overlap. Different reported languages can match only on these strict anchors and compatible markers. The limited English/German/Slovenian action vocabulary is a baseline, not semantic translation or a comprehensive negation detector.
- Complete-link grouping: every member pair must have direct evidence. Deterministic ordering; no transitive chaining, URL-based event identity or source independence claims. At most 80 observations, 100 mentions, four mentions per article, 20 members per event.
- Source publication and provider observation time stay separate from event-day candidates. The latter must literally occur in the source span. Unknown dates and capture times remain unknown. Earliest supplied capture is not original reporting. Known timestamps after the explicit cutoff are rejected.
- Stable event IDs derive from seed mentions and origin lineage. With a supplied previous snapshot, unambiguous membership growth preserves the ID; changed membership/split/merge gets new IDs with predecessor revisions. Old events absent from the current snapshot are reported, not declared deleted. No persistent revision history is created; callers must retain previous snapshots for replay.
- Output contains original observations, typed event candidates, pair rationale, timelines and lineage. All occurrence statuses are unknown. Neither similarity nor matching annotations proves an event occurred. Independent-source and original-reporting conclusions are deferred to V5.

Reference: [IPTC NewsML-G2 Guidelines](https://www.iptc.org/std/NewsML-G2/guidelines/) distinguishes persistent event concepts, event details and news coverage. The implementation uses these as design principles, not a claim of standards conformance.

Evaluation: synthetic regression only; held-out event-clustering precision/recall/F1, independent labels, cross-language accuracy, richer event entity/date extraction and live workflow acceptance remain outstanding. Deliberate abstention sacrifices recall; don't claim production accuracy or general multilingual understanding.
